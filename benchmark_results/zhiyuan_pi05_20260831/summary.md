## TensorRT-Edge-LLM（Thor）验证

- Thor 现有仓库为 TensorRT-Edge-LLM v0.6，TensorRT 10.13.3.9；现有 Python 环境缺少 NVPL/cuDSS/cuDNN 搜索路径，复用机器已有同版本动态库后，导出工具可以正常启动。
- 对原始 Pi-0.5 checkpoint 实际执行 `export_llm`，在模型加载阶段失败：该目录是 LeRobot `type=pi05` 配置，不是 Edge-LLM 所需的 Hugging Face `model_type` 配置。
- 官方支持表仅包含 Llama、Qwen、DeepSeek、Nemotron，以及 Qwen/InternVL/Phi-4 VLM；没有 PaliGemma/Gemma、Pi-0.5 或 VLA action expert。
- 这不是改配置即可绕过的问题：完整 Pi-0.5 还包含 SigLIP、双 Gemma 路径、AdaRMS 动作专家和 5/10 步 flow-matching；Edge-LLM 当前 C++ runtime 是 token 生成流程。要得到完整 TensorRT-Edge-LLM 性能，需新增模型封装、ONNX 导出、TensorRT 构建配置及动作运行时后再做数值对齐。因此当前没有可报告的完整 TensorRT-Edge-LLM 耗时或精度值，不能用 TorchAO 数字冒充。

## 结论与限制

- R1 的频率正常：RPU 总线和 R52 为 800 MHz，8 个计算核为 1.6 GHz；此前耗时偏长来自运行时整套版本和 C400 配置没有同时对齐，不是降频。
- R1 的 Graph 均为 READY，构建与重放结果 bit-equal，无 recapture，cache invariant 正常。
- 完整 451 层激活感知模型在 R1 上的 step=5 中位数为 167.19 ms，达到并略优于历史约 173 ms 的目标。
- 当前精确 checkpoint / 量化 / 输入组合仍是 Source-only 自定义验证配置，不能继承仓库公开模型的认证结论。
