# Restricted runtime assets

[简体中文](runtime_assets.zh.md) | English

RhinoForge source does not contain the Rhino Launch binary development package
or the combined opaque operator asset. For RhinoForge v1.0.0, an approved
distributor supplies both in one immutable delivery:

```text
RhinoForge-runtime-v1.0.0-r4.tar.gz
RhinoForge-runtime-v1.0.0-r4.tar.gz.sha256
```

The archive is compatible with the RhinoForge v1.0.0 **release**. It does not
contain RhinoForge source, models, quantized checkpoints, or the board SDK, and
is not covered by the source repository's Apache-2.0 license. Read
`DISTRIBUTION_TERMS.txt` before use.

## Delivery layout

After outer-archive verification and extraction, the directory has this shape:

```text
RhinoForge-runtime-v1.0.0/
├── RELEASE.txt
├── README.txt
├── DISTRIBUTION_TERMS.txt
├── SHA256SUMS
├── <launch-package-file>
├── <opaque-operator-asset>
└── <opaque-operator-asset>.kernels
```

`RELEASE.txt` is the only source for the runtime-set ID, compatible RhinoForge
release, Launch package filename/version, operator filename/version, adjacent
manifest filename, status, download flag, and checksum scope. `SHA256SUMS`
covers the three runtime payloads: Launch, the opaque operator asset, and its
adjacent manifest.

The `.kernels` file is release metadata generated by the distributor from the
reviewed public host-side reachability contract and bound to the exact asset.
It is not an operator source file and does not expose the opaque payload's
contents. Keep it adjacent to the asset without modification.

## 1. Obtain the archive and checksum

Normally an internal delivery owner downloads and verifies both files, then
transfers the pair to an approved customer. Customers repeat the verification.
Do not publish either file or forward it to an unapproved recipient.

If the distributor supplies a versioned authorized URL, download the same pair
as follows. Otherwise place the two delivered files in one local directory and
continue with the next section.

```bash
set -e
export RHINOFORGE_RUNTIME_BUNDLE_URL="<distributor-provided-runtime-v1.0.0-r4-URL>"
export RHINOFORGE_RUNTIME_ARCHIVE="RhinoForge-runtime-v1.0.0-r4.tar.gz"
curl -fSLO "${RHINOFORGE_RUNTIME_BUNDLE_URL%/}/$RHINOFORGE_RUNTIME_ARCHIVE"
curl -fSLO "${RHINOFORGE_RUNTIME_BUNDLE_URL%/}/$RHINOFORGE_RUNTIME_ARCHIVE.sha256"
```

Credentials stay outside the source checkout and model TOML files. For an
authenticated channel, verify the server identity using the fingerprint or
certificate supplied through a separate trusted path.

## 2. Verify and extract the delivery

From the directory containing the pair:

```bash
set -e
export RHINOFORGE_RUNTIME_ARCHIVE="RhinoForge-runtime-v1.0.0-r4.tar.gz"
sha256sum -c "$RHINOFORGE_RUNTIME_ARCHIVE.sha256"
tar -xzf "$RHINOFORGE_RUNTIME_ARCHIVE"
cd RhinoForge-runtime-v1.0.0
cat DISTRIBUTION_TERMS.txt
```

The outer checksum detects transfer corruption. The approved delivery channel
and distributor establish provenance; a checksum received from an unrelated
source does not.

## 3. Validate the release mapping and payloads

Fail closed unless this exact metadata is present. Derive every payload
filename from `RELEASE.txt`; do not hardcode or rename an operator file:

```bash
set -e
grep -qx 'status=active' RELEASE.txt
grep -qx 'download_enabled=true' RELEASE.txt
grep -qx 'compatible_rhinoforge_release=v1.0.0' RELEASE.txt
grep -qx 'checksum_scope=all_runtime_payloads' RELEASE.txt

export RHINOFORGE_RUNTIME_SET="$(sed -n 's/^runtime_set=//p' RELEASE.txt)"
export RHINOFORGE_LAUNCH_PACKAGE="$(sed -n 's/^launch_package_file=//p' RELEASE.txt)"
export RHINOFORGE_OPERATOR_ASSET="$(sed -n 's/^operator_asset_file=//p' RELEASE.txt)"
export RHINOFORGE_OPERATOR_KERNEL_MANIFEST="$(sed -n 's/^operator_kernel_manifest_file=//p' RELEASE.txt)"

case "$RHINOFORGE_RUNTIME_SET" in ""|*/*) echo "invalid runtime-set ID"; exit 1;; esac
case "$RHINOFORGE_LAUNCH_PACKAGE" in ""|*/*) echo "invalid Launch filename"; exit 1;; *.tar.gz) :;; *) echo "invalid Launch filename"; exit 1;; esac
case "$RHINOFORGE_OPERATOR_ASSET" in ""|*/*) echo "invalid operator filename"; exit 1;; *.ref) :;; *) echo "invalid operator filename"; exit 1;; esac
test "$RHINOFORGE_OPERATOR_KERNEL_MANIFEST" = "$RHINOFORGE_OPERATOR_ASSET.kernels"
test -f "$RHINOFORGE_LAUNCH_PACKAGE"
test -f "$RHINOFORGE_OPERATOR_ASSET"
test -f "$RHINOFORGE_OPERATOR_KERNEL_MANIFEST"
sha256sum -c SHA256SUMS
export RHINOFORGE_BUNDLE_DIR="$PWD"
```

`sha256sum` must report success for exactly the three named runtime payloads.
Do not continue after any metadata, filename, or checksum failure, and never
mix files from different runtime sets.

## 4. Install without root

Extract Rhino Launch into a versioned, user-owned prefix derived from the
manifest filename:

```bash
export RHINO_LAUNCH_ROOT="$HOME/.local/opt/${RHINOFORGE_LAUNCH_PACKAGE%.tar.gz}"
mkdir -p "$HOME/.local/opt"
tar -xzf "$RHINOFORGE_LAUNCH_PACKAGE" -C "$HOME/.local/opt"
test -f "$RHINO_LAUNCH_ROOT/lib/cmake/rhino_launch/rhino_launchConfig.cmake"

export CMAKE_PREFIX_PATH="$RHINO_LAUNCH_ROOT${CMAKE_PREFIX_PATH:+:$CMAKE_PREFIX_PATH}"
export LD_LIBRARY_PATH="$RHINO_LAUNCH_ROOT/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
```

Install the operator asset and adjacent manifest together, outside the source
checkout and Python environment:

```bash
export RHINOFORGE_RUNTIME_DIR="$HOME/.local/share/rhinoforge/runtime/$RHINOFORGE_RUNTIME_SET"
install -d "$RHINOFORGE_RUNTIME_DIR"
install -m 0644 "$RHINOFORGE_BUNDLE_DIR/$RHINOFORGE_OPERATOR_ASSET" "$RHINOFORGE_RUNTIME_DIR/"
install -m 0644 "$RHINOFORGE_BUNDLE_DIR/$RHINOFORGE_OPERATOR_KERNEL_MANIFEST" "$RHINOFORGE_RUNTIME_DIR/"

export RPU_KERNEL_LIB_PATH="$RHINOFORGE_RUNTIME_DIR/$RHINOFORGE_OPERATOR_ASSET"
test -r "$RPU_KERNEL_LIB_PATH"
test -r "$RPU_KERNEL_LIB_PATH.kernels"
```

RhinoForge links the external Launch library and reads the one combined asset
selected by `RPU_KERNEL_LIB_PATH`; it does not copy either into the Python
package. Keep the operator asset opaque and unchanged. Do not split it, inspect
its contents, generate a replacement manifest, or configure additional
operator-library paths.

Continue with [Getting started](getting_started.md#4-install-rhinoforge-in-a-fresh-environment)
for the regular source install, validation, exact Qwen3-0.6B download, TOML
checks, and inference.

## Updating or revoking a delivery

A published runtime set is immutable. Install a replacement under its new
runtime-set directory; never overwrite an existing set. If the distributor
revokes a delivery, stop using it, delete that version, and move only to the
replacement named by the distributor. RhinoForge does not download, update, or
revoke restricted assets automatically.
