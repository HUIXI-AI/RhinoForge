# 模型验证

简体中文 | [English](validation_policy.md)

验证应直接回答本次修改的问题，采用最小且有效的检查，复用适用的已有结果。

- 受影响的 host 测试运行一次；有针对性的检查已通过时，不扩大到完整测试集。
- RPU 执行路径有变化时，每条路径选一个代表用例。普通回放检查使用 3–10 次；
  性能检查使用 2 次预热、5–10 次测量，保持 checkpoint、精度和输入工作量一致。
- 仅检查改动相关的边界，例如权重变换或 KV 写入前的拒绝、输入更新、保留输出、
  BUILD/REPLAY 所有权；不附加无关生命周期或数值检查。
- 错误 shape、非法值、陈旧输入、错误执行路径和缓存破坏属于正确性问题。
  确认计算路径正常后，普通累计误差和量化差异只记录；不使用统一 cosine 阈值，
  不要求所有生成 token 完全一致。
- 请求行为得到证明、直接受影响的回归检查通过后停止；失败时只增加针对该假设的小规模诊断。

完整模型/精度/长度矩阵、超过 30 次的回放或基准、反复从零测量、加密证据闭环、
自定义发布框架和多层认证门禁均需用户明确要求。普通修复不启动模型移植认证流程。

板测前检查空闲并持有现有设备锁。环境必须隔离并绑定预期 worktree 和运行时资产。
报告实际测量范围和限制，不把其他模型或构建的结果移用于当前版本。
性能口径见[性能测量](performance.zh.md)。
